Starting and opening sessions in any folder

How Synopia gets you into the right folder, on a new machine and after a year of daily use. Each scenario compares the options where the choice is real, then walks the recommended flow. Every folder, title and count here is invented.

Recommended

  • New session asks where, with the answer ready. n in normal mode opens a folder list over the main area, drawn like Open session. The folder of the session on screen is selected, so n Enter starts there.
  • The list is the folders Synopia already knows: where sessions ran, plus the git worktrees of those repos. Nothing else is read to find folders.
  • A path you type completes on Tab, one folder at a time: one read of the folder typed so far, never more.
  • A path that doesn't exist can be made. One row, “Create folder <path> and start there”; Enter makes that one folder and starts in it. It is Synopia's only write to your disk.
  • Both lists match fuzzily, with the matcher from nota: letters in order, word starts and runs rank first, matched letters highlighted.
  • No open session means this list. First launch shows it in the main area, with only ~ in it.
  • Open session says it searches everything (“Newest 50 of 812”), and o in normal mode opens it.
  • A gone folder is named, not hidden. Its sessions read “Folder gone” and open read-only; Enter picks a folder to continue in.

Open questions

  1. Continuing a session in another folder: same id or a fork with a new id? Not checked: one scripted run must show whether the SDK resumes a session by id from another folder. The docs say a fork lands in the current folder's project.
  2. Is typing a path enough for a folder never used, or should the list also have one mouse row, “Choose in Finder…” (the macOS folder picker)?
  3. A new worktree from this list (git worktree add): later, or never? R3.3 says no new worktree yet.
  4. Should Synopia guess where a moved repo went (same git remote)? Proposed: no, you pick it.
  5. Should the other lists (the / command menu, the model picker) use the same matcher? Proposed: yes, as one change after this one.

Constraint: no directory scans, ever

  • Never list the home folder or walk folders, on first start or later. Listing ~ sets off a run of macOS privacy prompts: Desktop, Documents, Downloads, Pictures, Music, other apps' data, Library.
  • The folder list comes from what Synopia knows: the folders of its own sessions and of listSessions(), plus git worktree list in repos already in that list.
  • Path completion reads one folder, on Tab only: the direct children of the path typed so far. Never recursive, never as you type, never ahead of you. ~/ then Tab lists ~, only then.
  • A prompt you cause by typing is acceptable. ~/Documents/ then Tab may ask for access to Documents, because you asked to look there.
  • “Folder gone” stats known paths only, and late: the rows on screen, once per opening of the list. A stat inside a protected folder can prompt too, so a row there is checked only when you choose it.
  • The same late rule for git worktree list: repos on screen, and inside a protected folder only once you choose a row there.

Fuzzy search, from nota

The folder list and the Open list use the matcher from the author's music player, nota, which is fzf's algorithm in Swift. Synopia ports it to TypeScript in the backend, which sends each row's matched positions; the page only draws them. This page runs a JavaScript port of the same code, so the highlights below are computed, not drawn by hand.

What you typeWhat happens
How a word matchesIts letters must appear in the row in order, with gaps allowed: dmapp matches ~/dev/demo-app. Case and accents are ignored. Of all the ways a word can line up, the best-scoring one is kept.
Several wordsA space splits the query, and every word must match. Words match anywhere and in any order: csv invoice finds the same as invoice csv.
How rows rankEach matched letter scores 16. A letter at a word start earns a bonus: after a space 10, after / , : ; | 9, after other punctuation such as - or . 8, and a capital or digit after a lowercase letter 7. The first letter's bonus counts double. Letters in a run keep at least 4 each. A gap costs 3, then 1 for each letter it skips. A row's score is the sum over the words. Higher first; ties keep the list's order, newest first.
Session rowsThe row text is the title, then the folder. On a tie, the row with more of the match in its title goes first, as nota prefers a song's title over its album.
Folder rowsA repo and its worktrees stay together, and the group ranks by its best row, as nota ranks an artist by its best track.
HighlightsMatched letters are bold in the link blue. On the selected row, already blue, they are bold and underlined.

Taken from nota

Search/FuzzyMatch.swiftFuzzyMatch.match(_:in:scratch:): fzf's v2 algorithm, a score matrix over word and text, then a backtrace for the matched positions. The constants at the top of the file, bonusFor(_:_:) for word starts, charClass(_:), and fold(_:) and term(_:) for case and accents.
Search/SearchIndex.swiftSearchIndex.search(_:): split on spaces, every word must match, scores summed, positions joined, a tie goes to the row with more matches in its title (total * 64 + min(63, title matches)). LibrarySnapshot.filtered(to:): groups ranked by their best row, ties in list order.
Nota/LibraryRowView.swiftThe highlight style: accent and heavier type on a row, bold and underlined on the playing row. utf16Ranges(of:in:) turns positions into text ranges.

                        Rejected

                        • Starting at once and changing the folder in the header until the first message. It keeps “no dialog”, but the folder can't change once you send, and a wrong one shows only in small type.
                        • Two commands, one for “here” and one that asks. Two ways to do one thing; n Enter already costs one key.
                        • A welcome screen with a Finder button. A second way to start that you use once.
                        • The macOS folder picker as the main way. It knows nothing about the folders you used or their worktrees, and it is slow by key.
                        • Listing folders on disk to fill the list. Reading ~ and below sets off a run of macOS privacy prompts, and fzf-style listing would do it on every open.
                        • Folder first, then sessions, in Open session. Two steps every time, to fix a case typing already covers.
                        • Hiding sessions whose folder is gone. The history is still on disk and still worth reading.
                        • ⌘N and ⌘O in a File menu. The author's call: Synopia's keys stay single letters in normal mode, like i, x and b, with no new menu items.
