Is Claude thinking, or running something on my machine?

How a session shows where its time goes: to the model (thinking, writing a reply), to a command on your machine (a Bash step, a script, a git operation), or to background work after Claude's turn ended. It covers the sidebar row and its mark, the Main conversation card, the Working line and the running step. Every frame uses the app's own CSS and markup; only the marks and words of those four places are new. Every session, folder, command and output here is invented.

Recommended

  • The turning arc means the model. While Claude waits for the model, thinks or writes, the session keeps the agent's turning arc and "Working". The Working line adds the phase: "waiting for the model", "thinking", "writing the reply".
  • A command on your machine takes the shell mark. Once a Bash step of the turn has run 3 s, the arc gives way to the moving >_ in the sidebar box, on the Main conversation card and on the Working line. The words say "Running a command, 2m 14s". When the result lands the arc comes back.
  • The timer counts from when the command started. After Allow once it starts at 0 s, not at Claude's call. The Agent SDK sends the elapsed seconds while a tool runs, so a ticking timer also says the session is alive.
  • The step says what it runs. The Working line names the step, "Running Bash(Remove the worktree and its branch) 2m 14s", and the expanded step shows the command, its >_ state line, and "Output shows when it finishes · b, b sends it to the background to watch it".
  • A subagent in the foreground is the turn's step. It keeps the arc while it thinks, and takes the shell mark when its own command has run 3 s: "Running Bash(Build the docs) in Draft the release notes".
  • Background work after the turn is not your turn. The main agent rests: its still mark (the ring and core, no arc) and "Idle, 1 running in the background". The sub-line's mark moves, so the motion sits on what works. You can still type; a message starts a turn at once.
  • Your turn comes when nothing is left. The last background job has ended and Claude has read its report, or the job ended with no report to read (you stopped it).
  • MCP and web tools keep the arc. Their time goes to a server, not your machine. The Working line names them with their timer: "Working github create_pull_request 14s".

Requirement changes

  • R8.2, FR-STAT-02, working: the agent's turning arc while the main turn waits on the model, or on a step that isn't a command, or on a command that has run under 3 s.
  • New in R8.2, FR-STAT-02, running a command: the shell kind mark (moving >_) and "Running a command, 2m 14s", while the main turn's own step, or the step of the foreground subagent it waits on, is a Bash command that has run 3 s. Its time is the tool's elapsed seconds (tool_progress); in a session a terminal holds, from its tool_use.
  • New in R8.2, FR-STAT-02, idle: the main turn is over and Claude's background work runs (subagents, forks, background shells, monitors), or a finished job's report waits for Claude to read it. The still agent mark, "Idle, N running in the background", grey. It replaces the 2026-11-26 rule that made this your turn; the status.ts header's "Background work" paragraph goes with it.
  • R8.2, your turn: only once nothing of Claude's runs in the background and no report waits. "Whatever still runs in the background" goes.
  • R5.5, FR-VIEW-03: the Working line reads "Running Bash(…) 2m 14s" with the shell mark once the step has run 3 s, and "in <subagent>" for a foreground subagent's command. "Working" adds the model's phase. Still no line once the main turn is over.
  • R5.6, FR-VIEW-05: a running Bash step's state line has the shell mark, as a run's state line has, and its note adds "b, b sends it to the background to watch it".
  • R7.1, FR-BG-01: the Main conversation card's mark and word follow the session: the shell mark and "Running a command" (green tint); the still agent mark and "Idle" (grey tint).
  • R4.2, FR-SIDE-02: the state words gain "Running a command, 2m 14s" and "Idle, N running in the background".
  • Section 16, design notes: "Working is one arc for thinking and tools" becomes "one arc for the model; the shell mark for a command past 3 s", with why: the shell mark is a different shape, not a second arc, and 3 s keeps short steps from swapping it.

Open questions

  1. Is 3 s right? It matches when a run gets its panel card. Lower swaps the mark for most git calls; higher leaves a 5 s build on the arc. Recommended: 3 s.
  2. Does a background shell that never ends keep the session out of Your turn? A dev server can run all day. Recommended: yes, as you asked: the row says "Idle, 1 running in the background" and that is true; stopping the server makes it your turn.
  3. Should a long MCP or web call get its own mark? Recommended: no, not until a slow server is seen to mislead; the line names it with its timer.
  4. Live output of Claude's foreground command. The SDK documents no output while a foreground Bash runs. Recommended: keep "Output shows when it finishes" and the b, b hint; the shell storyboard's open check on the task's output file would settle whether a last line can show.
  5. A sooner "No updates" during a command. Not checked: one scripted run of a 5-minute sleep would show how often tool_progress comes. Recommended: if it is regular, "No updates" after 3 missed beats instead of 15 min.
  6. Does the foreground subagent's command reach the main row? Not checked: whether a subagent's tools send tool_progress. Recommended: yes, from the subagent's own transcript when they don't.

2. Waiting on the model

You ask for a summary of the cleanup. For 9 s nothing comes back from the model, then it thinks for 20 s, then it writes for 15 s. Claude starts the subagent "Profile the resize step" in the background, says so, and ends its turn. The subagent works on its branch for 6 min 58 s. Today the row reads "Your turn, 7 min" with the grey square, while its own sub-line turns. That is not your turn: Claude will read the subagent's report and go on. You can still type at any time.

Checked against the visual rules. Running things move: the subagent's dot keeps orbiting in the sub-line and on its card. Still things don't: the main agent runs nothing, so its mark stands still. Shape carries meaning: the ring and core with no arc is the agent's own shape at rest, not the square (your turn, stopped) and not the arc (working). Edge cases

Rejected

  • A new mark for "a tool runs", whatever the tool. It would mean learning a sixth running shape; the shell mark is already the sign for a command on your machine.
  • Swapping the mark on every step at once. A turn of quick git status and Read steps would flicker between two marks, the reason "one arc for thinking and tools" won before.
  • Showing the arc at a different speed for tools. Speed alone is hard to judge in passing (section 16).
  • "Thinking" in place of "Working" for the model. Claude also writes and waits for the first word; "Working" stays the one word, and the phase follows it on the line.
  • A live last line of a foreground command from a guessed file path. Synopia takes only paths the transcript names (open question 4).
  • Counting your own ! runs as background work. They are yours; only a run of yours that waits for input reaches the sidebar, as decided.
