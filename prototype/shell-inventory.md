# Shell commands in a Claude Code session: what exists and how Synopia shows it

Input for `prototype/shell-storyboard.html`. Every way a shell command, or a process that behaves like one, shows up in a Claude Code session, and how Synopia shows each one on 2026-11-26 (branch `synopia-improvements`, commit 4c7ea36).

Sources: the Claude Code docs read on 2026-11-26 (`interactive-mode`, `tools-reference`, `sub-agents`, `hooks`, `statusline`, `commands`, `agent-view`, `settings-reference`, `mcp`, `sandboxing`, `plugins/components` under `https://code.claude.com/docs/en/`), `docs/Claude Code transcripts.md` ("Bash mode records", "Background work", "Background output"), `docs/Agent SDK.md` (`perTaskStopAffordance`, "`backgroundTasks()` and the 2 s gap", "Task notifications", live runs PR-2 and MC-2), `docs/requirements.md` (R5.5, R5.6, R5.13, R7.1, R7.2, R8.2, R9.4, R9.5, R9.8), and the page code (`app/web/js/transcript.js`, `bg-view.js`, `rail.js`, `sidebar.js`, `creds-line.js`).

Words used in the table:

- **Row**: the item in the main transcript (or in a subagent's transcript, for a subagent's own work).
- **Live line**: the "Working …" line at the transcript's end (R5.5).
- **Card**: a card in the background panel on the right (R7.1); a **Past line** is its line after it ends.
- **Shell view**: the shell's or monitor's output opened in the main pane (R7.2).
- **Dock**: the panel's last row, where the message box and the needs-you cards sit.

## What the table shows

- Synopia shows shell work in four places today, each with its own rules: the step row (rows 1 to 6, 8, 9), your `!` band with an inline input line (rows 13 to 16), the background panel's card and shell view (rows 3 to 6, 12 to 16), and the dock (row 18).
- Input is taken in three places: under the `!` row in the transcript, in the shell view of a `!` run, and in the dock for the credential refresh.
- Only your `!` runs and the credential refresh can take input. Claude's Bash and Monitor have no stdin; a Claude command that waits for input hangs to its timeout.
- Stopping works for your `!` run (Esc, Esc in the main view) and the refresh (Cancel). Claude's background shells and monitors can't be stopped from Synopia (Q11).
- Claude's foreground Bash is the only run whose output Synopia can't show while it runs. Its output lands in the tool result at the end; once it moves to the background, its output file is named and the shell view shows it live.
- A run that ends at once (row 14) still gets a card and a Past line. A long Claude foreground Bash (row 2) gets none.
- Nothing in the sidebar or the card says a command waits for input (row 15).
- Rows 7, 19 to 25 are out of the transcript. Synopia shows none of them as a shell, except the MCP sign-in's waiting row.
