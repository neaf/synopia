## How to run

- `(cd app/backend && npm ci)` once, then `app/build.sh` builds `build/Synopia.app`; `open build/Synopia.app` runs it on `~/Library/Application Support/Synopia`.
- `app/dev.sh` runs the backend alone for Chrome (state in `app/.dev-state/`); `app/dev.sh --fake` plays the fake driver over the fixture tree, with no model calls.
- `app/check.sh` runs every check (backend tests, shell type check, page script syntax), one pass or fail line per part. Page checks over headless Chrome: `app/web/dev/cdp/run.sh <dnd|keys|menu|csp|preview>`.
- A test app on its own state: `open --env SYNOPIA_STATE_DIR=/tmp/s --env SYNOPIA_SNAPSHOT=/tmp/s.png build/Synopia.app`; quit the app with `pkill -TERM -x Synopia` (the daemon goes on: stop it with `kill -TERM` of the pid in `<state-dir>/daemon.json`, or `POST /api/stop?token=`). `app/README.md` has the same commands.

## Known limits

- The Now line follows 20 s (the writer's debounce) after a turn, background work or a waiting card changes, not at once.
- Until a folder's menu first arrives (1 to 5 s, once per folder: `menu-cache.json` keeps it after) the header names the model from its id (`modelLabel` in `md.js`), which can differ from the menu's own name.
- Not restored after a reload or relaunch: the preview's change marks, the slash menu, a viewer on pasted (blob) images. A SIGKILL of the daemon loses at most the last second of UI state.
- Backend updates: a message sent in the few milliseconds the idle handover takes is dropped (the old daemon handles nothing once stopping). A new daemon whose code loads but fails later (after `loaded`, say reading state) is a lost daemon: the shell starts one after 20 s, and the error view shows if that fails too. Session processes are ended by the handover (they were idle) and resume on the next message, as after Stop All Work.
- Paths map only the real path of `/tmp` and of home back (`paths.ts`); other links (a project folder reached through a symlink) show their real path.
- A task ended by the SDK's `task_notification` between turns is kept in memory only; the JSONL's own notification (written at the next turn) or the process-end mark covers a restart.
- The Open list lists the 50 newest sessions per filter, so an older one in a busy folder can't be reached from it.
