Choosing a project when you start

How Example app gets you into the right project, on the first day and after a year. Each scenario compares the options where the choice is real, then walks the recommended flow. Every project, title and count here is invented.

Recommended

  • New item asks which project, with the answer ready. The project on screen is selected, so ⌘N Enter starts there.
  • The list is every project you have used, newest first. Typing filters.
  • A deleted project is named, not hidden. Its items read “Project gone” and open read-only.

Requirement changes

  • R2.1: New item opens the project list instead of starting at once. The default-project setting goes.
  • New R2.7: items whose project is gone open read-only.

Open questions

  • Should a typed name that matches nothing offer “Create project …”? Shown here; it is the only write the app would make.
  • Not checked: whether the import keeps the project of each item. One scripted import settles it.

Rejected

  • Two commands, one for “here” and one that asks. Two ways to do one thing; ⌘N Enter already costs one key.
  • The system folder picker as the main way. It knows nothing about the projects you used, and it is slow by key.
